# Эмуляторы IoT: контракт для сервиса integration

Один контейнер `programmisto_emulators` запускает девять независимых устройств.
Integration может опрашивать их HTTP API и отправлять команды. Это локальная
симуляция: она пока не пишет данные в Redis/ClickHouse и не отправляет их в Ujin.
Ниже описано фактическое поведение текущего кода, а не API будущего production-сервиса.

## Запуск и настройки

Из корня репозитория:

```powershell
docker compose up -d --build --wait
curl.exe --fail http://localhost:8098/health
docker compose logs --tail 50 programmisto_emulators
```

Состав устройств, серийные номера и порты: [`fleet.json`](../../../backend/emulators/fleet.json).
Для применения изменений пересоберите контейнер. В корневом `.env` можно задать
`EMULATOR_INTERVAL=1` — реальную паузу между шагами модели в секундах. Каждый шаг
равен одной условной секунде; положительный интервал меньше 1 ускоряет симуляцию.
Состояние устройств хранится в памяти и сбрасывается при рестарте.

Из контейнера integration используйте имя **`programmisto_emulators`**, а не
`localhost`. С хоста используйте `localhost`. Пароли и токены не нужны; HTTP API
эмуляторов не имеет аутентификации. Опубликованные порты привязаны к localhost хоста.

| Устройство | `family` | Серийный номер | Порт |
| --- | --- | --- | --- |
| Термостат | `thermostat` | `local-thermostat-001` | 8099 |
| Датчик протечки | `leak` | `local-leak-001` | 8100 |
| Хаб трёх датчиков протечки | `hub` | `local-hub-001` | 8101 |
| Электросчётчик | `counter` | `local-counter-001` | 8102 |
| Светильник | `light` | `local-light-001` | 8103 |
| Вентиляция | `ventilation` | `local-ventilation-001` | 8104 |
| Пожарный датчик | `fire` | `local-fire-001` | 8105 |
| Шлагбаум | `barrier` | `local-barrier-001` | 8106 |
| Лифт, 5 этажей | `elevator` | `local-elevator-001` | 8107 |

Например: `http://programmisto_emulators:8102/state` из integration,
`http://localhost:8102/state` с компьютера разработчика.

## HTTP-контракт

| Запрос | Результат |
| --- | --- |
| `GET :8098/health` | Общий health: HTTP 200, если все процессы живы и каждый `/state` отвечает; иначе HTTP 503 |
| `GET :8098/devices` | Тот же JSON со списком `family`, `serial`, `port`, `status` |
| `GET :<порт>/state` | Полный снимок сигналов устройства: объект `имя → значение` |
| `GET :<порт>/declaration` | Массив описаний сигналов: права, единицы, диапазоны, варианты значений |
| `POST :<порт>/command` | Команда в формате `application/x-www-form-urlencoded`: `signal=имя&value=значение` |
| `POST :<порт>/` | Команды в JSON-обёртке `recv`, пример ниже |
| `GET :<порт>/` | HTML-панель для ручной проверки |

Health флота возвращает, например:

```json
{"status":"healthy","devices":[{"family":"thermostat","serial":"local-thermostat-001","port":8099,"status":"healthy"}]}
```

Здесь массив сокращён; в стандартной конфигурации в нём девять устройств.
Если процесс устройства завершается, весь флот перезапускается контейнером.
Не используйте служебный `GET /shutdown` в integration: он завершает устройство.

### Чтение показаний

```powershell
curl.exe --fail http://localhost:8099/state
curl.exe --fail http://localhost:8099/declaration
```

Пример элемента `/declaration`:

```json
{"name":"target_temp","title":"Цель","control":"range","management":"rw","kind":"setting","group":"setting","measure":"°C","min":5,"max":35}
```

`management`: `r` — только показание; `rw` — чтение и команда; `w` — действие.
Снимок `/state` включает и `w`-поля, но их значение **не является результатом
выполнения команды**. `kind`/`group` разделяют свойства, возможности и настройки;
`control` — подсказка для интерфейса, не строгий JSON-тип. Ключи `layout`
в JSON строковые, хотя значения сигналов могут быть числами.

### Отправка команды

```powershell
# Термостат: цель 25 °C
curl.exe --fail -X POST http://localhost:8099/command -d "signal=target_temp&value=25"

# Свет: включить и установить яркость
curl.exe --fail -X POST http://localhost:8103/command -d "signal=lamp&value=1"
curl.exe --fail -X POST http://localhost:8103/command -d "signal=brightness&value=60"

# Шлагбаум: открыть
curl.exe --fail -X POST http://localhost:8106/command -d "signal=open_cmd&value=1"

# Лифт: вызвать на третий этаж
curl.exe --fail -X POST http://localhost:8107/command -d "signal=call_requested&value=3"
```

JSON-вариант для клиента integration: POST на корень порта устройства
с `Content-Type: application/json` и телом:

```json
{"recv":[{"command":"management","id":"local-light-001","lamp":1,"brightness":60}]}
```

Форма `/command` преобразует числовые строки в числа; JSON-вариант передавайте
с числовыми значениями, а не строками. `id` в текущем обработчике не проверяется:
**адрес и порт выбирают устройство**. Нельзя отправлять все команды на один порт
и рассчитывать на маршрутизацию по `id`.

Ответ: `{"error":0}`; при пойманном исключении — `{"error":2,"message":"..."}`.
Оба ответа могут иметь HTTP 200, поэтому проверяйте тело. Неизвестный сигнал
или запись в `r` сейчас игнорируются и также могут вернуть `error:0`.
Это не подтверждение физического действия: проверяйте допустимость команды
по декларации и повторно читайте состояние. Движение лифта/шлагбаума и изменение
температуры завершаются за несколько шагов. Общая проверка диапазонов на стороне
эмулятора не реализована: её должен делать integration.

## Сигналы каждого устройства

В таблицах указаны **начальные значения из моделей**; JSON-примеры — снимки
запущенного стенда и могут отличаться при следующем запросе. Числа могут приходить
как целые или дробные. У всех устройств есть `fw` (`r`, строка `emul-1.0`).

## Особенности сценариев

- **Термостат:** `mode`: 0 — выкл, 1 — нагрев, 2 — охлаждение, 3 — авто.
  `output`: 0 — нет воздействия, 1 — нагрев, 2 — охлаждение. `fault=1` останавливает
  регулирование. Командой доступна цель 5–35 °C.
- **Протечка:** самотест сбрасывает внутреннее состояние в «сухо» на следующем
  шаге. `leak` и `tamper` нельзя менять через `/command`.
- **Хаб:** `leak_sensors` — строка вида `"010"`, по символу на датчик, а не число.
  `mute=1` выключает сирену, но не сбрасывает сам факт протечки.
- **Счётчик:** в стандартном флоте только электричество. `total`, `kvh_t1`,
  `kvh_t2` — накопительные значения; `power_w` — текущая мощность.
  `report_period` сейчас не меняет частоту публикации. Значения синтетические,
  для проверки интеграции, а не расчёта реальных начислений.
  Класс также поддерживает воду/тепло через `--resource` одиночного CLI,
  но текущий `fleet.json` эти параметры не передаёт. Вариант с отключением
  `load_relay` для неэлектрических ресурсов требует исправления модели.
- **Свет:** при включении `lamp=1` активируется таймер `offline_timeout`,
  если он больше нуля. Сначала задайте таймер, затем включайте лампу.
- **Вентиляция:** `mode`: 0 — выкл, 1 — авто, 2 — ручной. В авто-режиме модель
  сама меняет `fan_speed`; для ручной скорости сначала задайте `mode=2`.
  В режиме «выкл» значение `fan_speed` может сохранять прежнее показание,
  хотя расчётный поток остановлен.
- **Пожарный датчик:** `alarm=1`, когда задымлённость достигает `threshold`;
  `duty` при этом становится 0. `self_test=1` только пишет результат в лог,
  отдельного сигнала результата нет. Дым постепенно уменьшается.
- **Шлагбаум:** `state`: 0 — закрыт, 1 — открывается, 2 — открыт,
  3 — закрывается, 4 — удержание. `open_cmd=1` — импульс, поле сбрасывается в 0.
  После открытия срабатывает `hold_time`. Оценивайте выполнение по `state`,
  а не по значению команды.
- **Лифт:** `direction`: 0 — стоит, 1 — вверх, 2 — вниз; `door`: 0 — закрыты,
  1 — открыты. `floor_destination=0` означает отсутствие активной цели.
  Вызовы допустимы на этажи 1–5; модель хранит одну текущую цель, а не очередь.
  `emergency_btn` **переключает** аварийное состояние при каждом вызове,
  включая повтор команды: автоматический retry может снять аварию.
  `floor_changed` хранит последний пройденный этаж, а не журнал событий.

Демо-инъекции протечки, дыма, препятствия и неисправности сейчас доступны только
методами Python (`set_wet`, `set_smoke`, `set_obstacle`, `set_fault` и внутренние
датчики хаба). HTTP-ручки для них нет. Обычный опрос не гарантирует появление
каждой аварии: не подменяйте `r`-сигналы командами ради такого теста.

## Как подключать к integration

1. Получить список экземпляров на `:8098/devices`; сохранить связь
   `(family, serial, port)`. По каждому порту получить `/declaration`.
2. Опросить `/state`, например раз в секунду с тайм-аутом. Это снимок, не поток
   событий: кратковременные изменения между опросами можно пропустить.
3. Сопоставить строковый `serial` с внутренним UUID устройства и его организацией/
   зданием из PostgreSQL. Ни UUID, ни tenant-контекст в `/state` не передаются.
4. Преобразовать сигналы в общую модель: числовые значения и 0/1 — телеметрия,
   переходы аварий/доступности — события; `fw` и строковые маски не помещать
   напрямую в `telemetry.value` типа Float64.
5. `/state` не содержит времени измерения, `event_id` и качества. Время опроса
   можно хранить как время наблюдения, но нельзя выдавать его за время измерения
   устройства. Правило заполнения обязательного `measured_at` в ClickHouse
   согласовать отдельно. ID и метаданные создаёт integration; при повторной
   доставке одной записи сохранять тот же ID.
6. Проверять права пользователя, `management` и диапазон перед отправкой команды.
   Ответ и наблюдаемый результат хранить отдельно. Не считать повтор одинакового
   показания новым измерением без согласованного правила выборки.

При сетевой ошибке отмечайте недоступность и время последнего успешного опроса;
не интерпретируйте последнее известное показание как свежее. Нельзя гарантировать
exactly-once команды или полный аудит событий одним опросом `/state`.

### Что выходит из эмулятора помимо HTTP

При старте модель публикует все `r/rw`-сигналы, затем — изменившиеся.
Сейчас публикация только печатается в stdout как `JOURNAL`, например:

```json
{"call":"publish","path":"/api/import_device/update-device-signal/","data":[{"sn":"local-thermostat-001","s":"temperature","v":21.8,"c":"emul_thermostat"}]}
```

`sn` — серийный номер, `s` — сигнал, `v` — значение, `c` — модель. В журнале
команды формат другой: `{"call":"command","name":"lamp","value":1}`,
он не содержит серийного номера. Строки нескольких процессов могут перемешиваться:
**stdout пока не является транспортом для integration**.

В Ujin-публикации есть особенность `wire_value`: числовой ноль обычно заменяется
на `0.001`. В HTTP `/state` остаётся настоящий `0`. Не смешивайте эти два формата
и не трактуйте `0.001` из Ujin как аварийную единицу без адаптера протокола.
